## Правило каждого рабочего запуска
CLOUD и LOCAL сначала читают README, QUEUE и три общих файла, затем актуальные собственные WORK/RESUME и issue #14. Не повторяют уже сделанное, не перезаписывают свежий чужой in_progress. После материального результата дополняют соответствующие журналы: уникальный ID, реальная дата/часовой пояс, автор, факт или решение, источник/commit, пройденные и непроведённые проверки, оставшийся hold.

Перед записью повторно читать SHA и сохранять чужие строки. При конфликте перечитать и объединить по ID, не применять force. Для независимого долговременного checkpoint допускается уникальный `events/YYYY-MM-DD/<run-id>.json`, затем общий индекс. В конце дня — фактическая сводка. Планы не считаются выполнением; без рабочего запуска нет фонового обновления.

LOCAL однократно добавляет это правило в свои существующие startup-инструкции, не перезаписывая их целиком. На момент обновления получение и установка правила локальным процессом ещё не подтверждены. До выборочной интеграции читать явно ветку **mira/research-night-20260918**, не предполагать наличие новых файлов в main.
