# Ассистент МИРА — первый рабочий сценарий

18.09.2026. Дополнение к MIRA-OMNI-20260918-01. Название по решению владельца: **Ассистент МИРА**. Анна / WEGC сохраняется для покупателей Пхукета.

## Реализовано

1. **Сохранение клиентского запроса.** В private journal добавлен `client_briefs`: рынок, тип, цель, бюджет исходными словами/валютой, район и сроки. Модель предлагает извлечённые критерии, код принимает только дословные цитаты из текущего сообщения. Каждый критерий хранит ID источника. Если рынок/тип неоднозначен, значение не угадывается.
2. **Продолжение диалога.** При следующем сообщении модель получает сохранённый brief. Система спрашивает только недостающие основные поля, максимум два вопроса за ответ. Неизвестный бюджет может быть явно записан словами клиента; это не означает, что его удалось проверить.
3. **Подбор из реального каталога.** `normalize_catalog` читает существующие публичные JSON feeds без новой CRM или копирования каталога в промпт. `shortlist` фильтрует рынок/тип и явно заданный район. Возвращает до трёх проектов со ссылкой, provenance и причиной совпадения. Точный тип важнее грубой категории: таунхаус из категории villa не объявляется виллой. Стабильный порядок по ID — это не рейтинг качества.
4. **Честное ограничение результата.** Цель, бюджет, сроки, наличие, цены и комиссия перечислены как непроверенные. Не применяется выдуманная конвертация валют. Любые унаследованные `commerciallyEnabled` или цена из feed не повышают результат до коммерческого предложения.
5. **Запись и handoff.** Brief и подборка записываются в локальной транзакции вместе с CRM Note outbox. По запросу проверки создаётся CRM Task с критериями и последней соответствующей подборкой, AI ставится на паузу. Формулировка не утверждает, что CRM/менеджер уже получили запись до подтверждения адаптера.
6. **Работа с пробелами.** Непокрытый вопрос попадает в private `knowledge_gaps` со статусом `needs_human_review`. Опциональный свободный `draft_reply` хранится только для проверки человеком; он не отправляется и не становится новым фактом автоматически.

## Подключение LOCAL

Предыдущий receipt LOCAL уже подтверждает принятие исходного пакета по ed2db2e9. Это дополнение той же задачи; принятый receipt не перезаписывать и установку CRM не повторять.

- Обновить package выборочно, запустить `python3 -m unittest discover -s tests -v` — текущий suite 53 тест.
- Существующий `MIRA_PROFILE=mira_agency`, scoped DB и KB сохранить. Для покупательского профиля этот сценарий запрещён конструктором.
- Установить `MIRA_CATALOG_CONFIG` на private JSON с записями `{path,market,source}`. `path` — абсолютный путь к актуальному repo feed, `market` — его фактический рынок (для `mira/catalog/data.json` это `phuket`), `source` — ссылка на этот источник, желательно с commit SHA. Для multi-market feed `market` берётся из самих записей. Не открывать произвольную загрузку URL из текста клиента.
- `worker.py` загрузит конфигурацию, нормализует записи и подключит DealFlow к общему Engine. Перезапуск bounded worker перечитывает файлы. Отслеживание свежести source feed и реальный inventory API остаются задачей product integration; эта версия не предоставляет live inventory.
- Модель возвращает `action=collect_brief|shortlist|request_specialist` и `criteria_updates={field:{quote:...}}`; схема описана в системной инструкции адаптера. Неподтверждённые цитаты отклоняются. Подбор выполняет код, модель не может подставить собственный project ID.
- CRM Notes содержат `client_brief`, `research_shortlist`, `next_action`; сопоставить это с фактическими custom fields только после проверки схемы Espo. Доставка через существующий scoped API user, затем receipt. Native CRM entity schema не угадывалась.

## Проверки

53/53 локальных тестов PASS: прежние 41 + 12 сценариев запроса/подбора. Проверены накопление критериев, отсутствие повторного вопроса о рынке, отказ придуманного бюджета, запрет buyer-профиля, невозможность подмены project IDs моделью, сохранение подборки при handoff, отличие townhouse/villa, review-only backlog, честный pending CRM, неоднозначный рынок и исходная валюта.

Отдельный smoke использовал 618 фактических записей `mira/catalog/data.json` и синтетический запрос. Получены три структурных совпадения; все остались research_only и без цены. `DEAL-SMOKE-REPORT.json` — техническое доказательство обработки, не рекомендация реальному покупателю и не подтверждение наличия.

## Что пока не закрыто

- Один активный клиентский brief на контакт агентства. Не использовать для нескольких одновременных покупателей без введения case ID; перед новым клиентом LOCAL должен явно архивировать/сменить case. Не считать это многоклиентской CRM.
- Свободный генеративный ответ пока только черновик для человека. Автоматические ответы — approved facts либо проверяемые шаблоны действий. Полноценная свободная sales-беседа требует отдельной оценки на реальной модели; локальные тесты используют stub.
- Подбор не проверяет бюджет, доходность, сроки сдачи, пригодность для жизни, точность унаследованных географических полей и коммерческие права. Район сопоставляется буквально; если формулировка не совпала, запрос уходит специалисту.
- Автоматические бронирования, встречи, договоры, публикация новых знаний и CRM custom-field mutations не добавлены. Источник истины для внешних действий — provider receipt.
- Live модель/аккаунты/CRM/site integration остаются LOCAL. Production не менялся, внешних сообщений не отправляли.

## Реальная приёмка

Один согласованный agency pilot: два сообщения с уточнением запроса → сохранённые критерии → исследовательская подборка → видимая CRM Note → просьба проверить условия → Task с подборкой → пауза AI → ручной resume. Отдельно показать отсутствие доступа этого сценария у Анны / WEGC. Вернуть фактические результаты и holds в существующий receipt MIRA-OMNI-20260918-01.

## Сохранённое исправление LOCAL
Свежий receipt LOCAL для ed2db2e9 сообщает успешную нативную Note/Task-проверку и HTTP 400 без исполнителя. Общий адаптер теперь требует server-configured `ESPO_TASK_ASSIGNEE_ID` и передаёт `assignedUserId` при создании Task. Не угадывать ID оператора. Проверка контракта включена в 53 теста CLOUD; реальную CRM проверял LOCAL, а не этот новый flow. При выборочном переносе сохранить локальные изменения private commit 6af4703.
