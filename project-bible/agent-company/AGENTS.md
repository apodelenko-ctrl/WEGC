# Правила исполнителей ACI

Область действия: только `project-bible/agent-company/` в ветках `agent-company/*`. Читать перед любой работой. Это внутренний протокол проекта, не правовое заключение.

## Перед началом

Прочитать README, Решения, WORK-STATUS, RESUME-STATE, agents/QUEUE.json. Проверить реальный HEAD и доступность зависимостей. Выбрать `ready` задачу или согласованную задачу проверки; не повторять `done` без причины. Записать исполнителя и фактический run ID, если runtime его выдал. Не придумывать run ID внешней системы.

## Выполнение

Материальный результат — файл, код, тест, проверенное доказательство или конкретный блокер. После результата обновлять очередь, Контроль-борд, WORK-STATUS и RESUME-STATE. Затем брать следующий независимый блок в пределах текущей сессии. Нельзя считать окончание ответа продолжающимся фоновым выполнением.

## Доказательства

Для фактов: первичный источник, URL, дата и предел применимости. Для действий: actual receipt. `vendor_statement` не равен `tested`. `submitted` не равен `approved`. `mock` не равен `production`. Наличие роли и промпта не равно её запуску. Юридические исследовательские документы не равны заключению назначенного юриста.

Не выдумывать цены, конверсии, выручку, даты исполнения и доступные credentials. Не копировать целые сторонние статьи. Конфликты источников и изменения выводов сохранять в журнале.

## Разрешённые действия сейчас

Чтение публичных источников; анализ; написание документов; локальный код без внешних эффектов; синтетические тесты; commit только в проектном каталоге отдельной ветки. Проектные выборы помечать как предложения до утверждения владельцем.

## Требуют отдельного owner approval

Внешние сообщения, формы, договорные согласия, реальная регистрация компаний, банковские/платёжные заявки, покупки, движение денег, выдача production-доступов, deployment и подключение платного постоянного runtime.

## Защита других проектов и данных

Не изменять main, МИРА, CLOUD-INBOX, корневой сайт и workflows. Не merge всей рабочей ветки в production. Не force-push. Не сохранять личные сведения, KYC, ключи, cookies, .env, банковские документы и закрытые коммерческие условия в публичной ветке. Секреты должны оставаться в отдельном секрет-хранилище с ограниченными правами.

## Definition of done

Артефакт существует; acceptance criteria проверены; отмечено, кто действительно исполнил работу; тестовый результат сохранён; зависимости не подменены; GitHub-публикация проверена; следующая задача и блокеры записаны. Для задач с внешним подтверждением одного нашего документа недостаточно.

## Протокол receipt

Использовать agents/RECEIPT-TEMPLATE.json. Поля: task_id, executor, runtime, status, evidence_paths, tests, external_actions, blockers. `not_started` — нормальный статус до реального запуска; пустой массив blockers не означает пригодности к production.
