# ACI-013 — проект среды выполнения агентов

2026-09-19 · ASTRA. Спецификация собственной системы, не утверждение о запущенном runner и не описание существующего продукта поставщика.

## Назначение

Превратить подготовленные роли и задачи в проверяемые попытки исполнения. Библиотека GitHub — источник спецификаций; operational state должен жить в приватной постоянной базе, а не только в редактируемом QUEUE.json. Два уровня агентов разделены: исполнители проекта ACI и будущие клиентские агенты бизнеса.

## Минимальные сущности

Task: id, revision, dependencies, assigned_role, permitted_tools, acceptance, status.

Attempt: task_id, attempt_id, worker_id, lease_owner, lease_expiry, fencing_token, heartbeat_at, input_commit, policy_version, status.

Result: attempt_id, artifact references, hashes, test command/exit code, evidence, exceptions, external actions, approval references.

Approval: реальный issuer, точное действие/payload hash, срок, статус и право отзыва. Работник не может выдать себе approval. Плановая роль не является полномочием.

## Цикл

Dispatcher выбирает ready задачу с завершёнными зависимостями → атомарно выдаёт lease → worker получает зафиксированный input commit и свой prompt → выполняет разрешённые действия в отдельной рабочей директории → отправляет heartbeat → сохраняет артефакты и receipt → reviewer проверяет acceptance → координатор публикует результат и обновляет очередь.

Worker не ставит окончательный done только потому, что LLM написал «готово». Должен существовать результат проверки и подтверждённая публикация. Независимый review не заменяется второй ролью того же авторского ответа.

## Сбои и повторения

Истёкший lease позволяет новой попытке забрать задачу; старый worker больше не может принять результат с устаревшим fencing_token. Повторные внешние действия сверяются по durable idempotency key и журналу. Неизвестный исход отправки не равен неудаче и не разрешает автоматическое повторное действие. Нужны outbox, reconciliation, retry policy и очередь исключений.

Лимиты времени, вычислений и расходов задаются конфигурацией после утверждения, сейчас unknown. В один runtime не передавать ключи всех операционных компаний. Tool access задаётся для роли и конкретной попытки; внешние тексты не могут менять owner policy.

## Разделение доверия

LLM предлагает и формирует артефакт. Детерминированный контроллер проверяет права, бюджет, статус approval и допустимость инструмента. Секреты доступны адаптеру, а не свободному контексту всех агентов. Публичная GitHub-ветка не содержит KYC, токены или полный операционный журнал клиентов.

## Первый реализуемый шаг без платных сервисов

ACI-025: локальный runner-симулятор со SQLite, fixture workers и тестами lease expiry, stale result, retry и восстановления. Это ещё не реальные LLM workers. После проверки архитектуры выбрать внешний runtime и модельный API, получить разрешения/бюджет и только тогда подключать живых исполнителей.

## Что требуется для настоящего запуска

Приватная среда; постоянная база и backup; secret store; разрешённый model API; выбранный инструментарий; ключи с минимальными правами; ограничения расходов; логирование и алерты; правила публикации; фактический run ID и receipt. Выбранный провайдер, credentials, бюджет и production deployment отсутствуют.

## Приёмка

Одна задача действительно получена внешним worker; input revision зафиксирован; heartbeat наблюдался; результат и тесты сохранены; stale attempt отклонён; kill switch блокирует новые действия; после рестарта состояние восстанавливается. До выполнения этого набора статус runtime — not_provisioned, а не «агенты работают постоянно».
