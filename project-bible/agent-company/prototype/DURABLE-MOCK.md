# Durable local mock — ACI-022 / ACI-023

2026-09-19 · execution-05 · реализовано ASTRA в текущей интерактивной сессии. Это локальная симуляция, не зарегистрированная компания, банк или production gateway.

## Реализовано

SQLite хранит записи заявок с версиями, квитанции идемпотентности, тестовые identities, сроки и отзыв полномочий. Изменение состояния, квитанция и событие записываются одной транзакцией BEGIN IMMEDIATE. Повтор с тем же ключом и payload возвращает прежний результат; изменение payload — конфликт. Авторизация выполняется до выдачи исторического результата. Опциональный expected_version защищает запись от устаревшего изменения.

Проверены независимые экземпляры API с общей базой, повторный запуск в другом процессе, конкурентные запросы, исключение и принудительное завершение процесса до commit. Эти проверки не доказывают защиту от аппаратной потери данных, распределённую exactly-once доставку или безопасность настоящих финансовых операций.

Обычный старый mock_http.py и lifecycle.py оставлены неизменными как baseline. Новая реализация использует исходную модель состояний и loopback HTTP-оболочку. Внутренняя связь с Lifecycle._records пока явная прототипная зависимость, не стабильный интерфейс storage adapter.

## Полномочия

Identity получает срок действия, список разрешённых заявок и action scopes при доверенном локальном provisioning. Клиент не выбирает роль по HTTP. Мандат дополнительно ограничен конкретной заявкой, agent_id, операциями и expires_at. В этом симуляторе application_id — будущая граница компании, не подтверждённый идентификатор настоящего юрлица.

POST /v1/identities/{id}/revocation отзывает один credential identity. POST /v1/agents/{agent_id}/revocation блокирует все ключи данного агента в контуре tenant/principal, включая повторный provisioning под тем же agent_id. Эти маршруты доступны только оператору без ограничения отдельной заявкой. Полный отзыв означает блокировку в данном ACI API, не отмену уже выполненных действий и не остановку внешних систем.

Операторский ключ — тестовое средство доступа, не KYC и не юридическое доказательство согласования. Проверенные principals и production identity provider не подключены. Не выдавать fixture credentials за настоящую проверку личности.

## Отличия HTTP-контракта от baseline

Существующие /v1/applications маршруты сохраняются. Для /mandates дополнительно обязательно expires_at: конечный Unix timestamp, строго в будущем по серверным часам. В остальных mutation payload допускается expected_version для существующей заявки. GET возвращает record_version, mandate_expires_at и mandate_effective. Последнее учитывает срок/отзыв мандата и глобальный отзыв agent_id, но не является обещанием наличия действительного внешнего банковского доступа.

Mutation response содержит receipt.id, replayed, result_is_historical и current_authorization_checked. Исторический snapshot не считается текущим состоянием — для него нужен GET. Replay операции требует всё ещё действующего мандата; повтор старой выдачи мандата после отзыва не восстанавливает доступ.

Ключ идемпотентности привязан к identity и маршруту. Переход между новыми credential identities не обеспечивает глобальную дедупликацию одной бизнес-операции; стабильный business operation ID и outbox ещё нужны до реального провайдера.

## Запуск

Python 3.10+ и стандартная библиотека. Рабочие файлы базы и credentials должны быть вне репозитория, в приватном локальном каталоге. Следующий пример содержит только технические параметры теста:

```bash
mkdir -m 700 "$HOME/aci-local-fixture"
python project-bible/agent-company/prototype/durable_api.py \
  --initialize \
  --state-db "$HOME/aci-local-fixture/state.sqlite" \
  --credentials-file "$HOME/aci-local-fixture/credentials.json"
```

Сервер печатает фактический loopback port; секреты не печатаются. Для рестарта использовать те же пути БЕЗ --initialize. CLI не перезаписывает существующую базу и не продлевает credentials автоматически. Стандартный TTL 3600 секунд — настройка локального fixture, не обещание SLA или юридический срок. Истёкший/отозванный ключ не становится действительным после рестарта.

```bash
python -m unittest discover -s project-bible/agent-company/prototype -p 'test_*.py' -v
```

## Что ещё нельзя считать готовым

Нет настоящих provider webhooks, outbox/reconciliation, EIN, платёжных операций, защиты журнала от администратора базы, шифрования документов, TLS, rate limiting, production auth, независимого security-review и постоянно работающих LLM-агентов. SQLite-аудит содержит успешные мутации; это не полный журнал всех отказов.

Backup проверен только как восстановление локального снимка в изолированную среду. Старый backup может содержать уже отозванные позже credentials и устаревшие квитанции. Восстановление production потребует безопасного сброса/сверки полномочий и внешних операций. Прототип нельзя публиковать наружу через туннель или reverse proxy.
