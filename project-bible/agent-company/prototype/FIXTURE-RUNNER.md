# Локальный fixture runner — ACI-025

2026-09-19 · execution-06 · ASTRA. Выполняемый код, не постоянно работающий LLM runtime.

## Что реализовано

Задачи и отдельные попытки сохраняются в SQLite через sqlite_store.py. Каждая задача имеет фиксированную спецификацию, зависимости, input_revision, предел попыток и статус. Claim атомарно выдаёт задачу одному worker и увеличивает fencing_token. Heartbeat может продлевать только действующий lease. После его истечения новая попытка получает новый token; поздний результат или heartbeat старого worker отклоняется.

Повтор enqueue с той же спецификацией идемпотентен; изменение спецификации для существующего task_id запрещено. Зависимости должны существовать до создания задачи, что исключает добавление цикла через будущую задачу. После провала зависимости зависимая задача остаётся ready, но не может быть выдана: это blocked-by-dependency поведение, не успешная работа.

Финализация записывает task, attempt, receipt и event одной транзакцией. Повторное подтверждение того же результата возвращает прежнюю квитанцию, а не создаёт второе завершение. Проверка результата детерминирована и доступна только для разрешённых fixture handlers. Worker не может завершить задачу одним сообщением «готово».

## Что именно выполняют workers

Только fixture.echo и fixture.count — локальные функции над явно синтетическим payload. Нет shell execution, внешних HTTP-вызовов, модельного API, отправки писем и настоящих бизнес-операций. Сохранённые роли ENGINEERING и другие не запускаются этим модулем автоматически. Очередь fixture задач не меняет agents/QUEUE.json проекта.

Фиксируются input_revision и его формат, но runner не скачивает и не исполняет код из этого commit. В demo используется сорок нулей как явный fixture marker, НЕ существующий GitHub SHA. В unit-тестах используется реальный известный baseline SHA; это тоже не означает remote checkout.

## Запуск

```bash
python project-bible/agent-company/prototype/fixture_runner.py
python -m unittest discover -s project-bible/agent-company/prototype -p 'test_*.py' -v
```

Demo создаёт временную локальную базу, последовательно исполняет две синтетические задачи с зависимостью, печатает квитанции и завершается. run_bounded требует конечного max_tasks; модуль не запускает бесконечный фоновый цикл. База demo удаляется при завершении; устойчивость persistent path отдельно проверена unit-тестами.

В execution-06 прошли 97 тестов всего: сохранённые 78 и 19 новых runner-тестов. Реальный demo также завершился с exit code 0. Evidence: [тесты](../agents/receipts/runner-tests.json), [demo receipts](../agents/receipts/fixture-runner-smoke.json).

## Границы доказательства

Lease/fencing защищают принятие результата в локальном Store, но не отменяют внешние действия устаревшего worker. До реальных API нужны transactional outbox, стабильный business operation ID, проверка полномочий перед отправкой и reconciliation. Завершение fixture задачи не является независимым security-review, профессиональным заключением или выполнением производственной задачи агента.

Тестовый worker и локальный HTTP-сервер были остановлены после прогонов. Для настоящего автономного исполнения всё ещё нужны выбранная приватная среда, model API, ограниченные credentials, бюджет и отдельное разрешение на deployment.
