# 04 — Платформа, данные и кабинет

## Принцип

На первом этапе не строим тяжёлую CRM. Агентства уже ведут клиентов в своих системах. Наша платформа должна решать только то, чего у них нет.

## Минимальный кабинет агентства

### 1. Каталог

Навигация:

страна → регион → застройщик → проект → тип объекта → конкретная доступная единица.

Фильтры:

- бюджет;
- тип объекта;
- срок сдачи;
- готов / строится;
- рассрочка;
- доходность / rental program, если подтверждена;
- комиссия застройщика;
- комиссия агентству;
- тип владения;
- район;
- специальные условия.

### 2. Подключение направления

Агентство ставит галочки по интересующим рынкам:

- Пхукет;
- Бали;
- Дубай;
- Вьетнам;
- другие по мере запуска.

Эти данные одновременно являются сигналом спроса для команды, которая подключает застройщиков.

### 3. Брендированные материалы

Минимум:

- PDF;
- ссылка на подборку;
- логотип и контакты агентства;
- без бренда платформы в клиентском режиме;
- возможность выбрать только нужные проекты.

### 4. Регистрация клиента

Поля:

- агентство / брокер;
- клиент;
- контакт или внутренний ID;
- проект / застройщик;
- дата;
- бюджет;
- комментарий;
- подтверждение регистрации застройщиком;
- срок защиты лида.

Цель — не вести CRM, а доказуемо фиксировать право на комиссию.

### 5. Сделка

Статусы:

- лид зарегистрирован;
- подтверждён;
- просмотр / консультация;
- бронь;
- договор;
- платёж;
- комиссия начислена;
- комиссия получена платформой;
- комиссия агентству выплачена.

### 6. Комиссия

Показывать:

- комиссия застройщика;
- доля агентства;
- доля платформы;
- условия начисления;
- ожидаемая дата;
- статус выплаты.

### 7. Платёжное сопровождение

Кнопка / запрос:

**«Клиенту нужна помощь с оплатой»**.

Минимальные поля:

- страна клиента;
- валюта средств;
- сумма;
- застройщик;
- валюта инвойса;
- срок оплаты;
- документ сделки.

Дальше запрос уходит на ручную обработку, пока процесс не стандартизирован.

## Что НЕ нужно в MVP

- полноценный pipeline продаж;
- телефония;
- задачи брокерам;
- email-маркетинг внутри кабинета;
- сложная автоматизация отдела продаж агентства;
- собственный мессенджер;
- мобильное приложение до подтверждения регулярного использования веб-кабинета.

## Данные о проектах

Нужен единый объект данных.

### Застройщик

- legal name;
- brand;
- country;
- region;
- website;
- contacts;
- sales contact;
- legal contact;
- reputation notes;
- projects;
- standard commission;
- enhanced network commission;
- payment terms;
- agreement status;
- last verified.

### Проект

- name;
- developer;
- country / region / district;
- coordinates;
- property type;
- construction status;
- delivery;
- price range;
- currencies;
- ownership structure;
- payment plans;
- commission;
- availability source;
- brochure / floor plans / renders;
- official source URL;
- date verified.

### Единица / inventory

Позже, когда есть официальный feed:

- unit ID;
- type;
- floor;
- area;
- bedrooms;
- view;
- price;
- discount;
- availability;
- payment plan;
- last updated.

## Источники данных

Приоритет:

1. официальный feed / API застройщика;
2. официальный sales kit;
3. официальный сайт;
4. подтверждение менеджера застройщика;
5. внешние агрегаторы только для discovery, но не как финальный источник цены и наличия.

Никаких выдуманных цен, комиссий, остатков или доходности.

## Что уже есть в WEGC

Полезные элементы:

- `ru/katalog.html`;
- `scripts/build-phuket-index.py`;
- `cloudflare-worker/wegc-kb.js`;
- проектные паспорта в `projects/`;
- существующий парсер и логика структуры полей.

Это нужно инвентаризировать и превратить в первый `Phuket dataset`, не переписывая всё с нуля.

## Архитектурный принцип на старте

Не строить огромную систему до подтверждения спроса.

Этап 1: статический / серверный каталог + простая авторизация + база агентств и лидов.

Этап 2: импорт данных и кабинеты.

Этап 3: API / white label / интеграции с CRM.

Этап 4: аналитика спроса, персональные рекомендации, автоматическое обновление inventory.

## Сетевые данные как актив

Платформа должна собирать не только сделки, но и **намерение агентств**:

- какие страны включили;
- какие проекты смотрят;
- что добавляют в подборки;
- какие бюджеты запрашивают;
- какие payment plans нужны;
- какие рынки не представлены, но востребованы.

Эти данные становятся основой переговоров с девелоперами и собственной рыночной аналитики.
