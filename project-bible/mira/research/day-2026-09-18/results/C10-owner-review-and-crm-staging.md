## Подготовка импорта без строительства новой CRM
C10 JSON — **промежуточная проверяемая структура**, не готовый файл Brevo и не заявление о нативной совместимости с Espo. Перед импортом LOCAL сначала разворачивает `defaults` на каждую запись. Любой неизвестный/отсутствующий маркетинговый допуск означает отсутствие отправки, не opt-in.

| C10 поле | Назначение в уже работающей CRM | Правило |
|---|---|---|
| id | существующий external/research ID либо строка MIRA research ID в Description | Сохранять стабильный ID, не создавать второй объект при повторе |
| name / website / city / country | карточка организации/Account и доступные штатные поля | Не создавать людей по названию компании |
| corporateRoute / sourceUrl / sourceCheckedAt | источник и заметка проверки | Публичный маршрут не согласие на рассылку |
| segment / discoveryQuestion | внутренний сегмент и задача менеджеру | Никакого автоматического обещания спроса |
| subject / hook / body / cta | библиотека черновиков, не исходящая очередь | Перед выпуском проверить текст и фактического адресата |
| licensingStatus / hold | отдельная заметка due diligence | Не писать «лицензия проверена» для шести BY |
| defaults.marketingPermission | unknown / marketing disabled | Не превращать в subscribed при импорте |
| defaults.sendApproved | false | Обычное разрешение на выбор CRM не переводит в true |
| defaults.accountImported | false до фактического отчёта | Успешная проверка JSON не импорт в CRM |

Новые пользовательские поля настраивать только при необходимости и штатным способом; реальные имена/тип полей сверить с установленной CRM. Если пригодная CRM уже работает — не мигрировать её ради этого файла. Нельзя менять memberships/Access/D1/права МИРА по этапу внешней CRM.
