# 10 — AI-операционная модель

Дата проверки: 2026-09-16.

## Зачем

Проект удобно вести как набор параллельных исследовательских потоков: агентства, застройщики, страны, конкуренты, legal cards, контент, качество данных. Но нельзя путать это с запуском 20 одинаковых чат-окон без единого формата результата.

## Рекомендуемая схема

### Координатор

Один главный поток отвечает за:

- декомпозицию;
- выдачу задач;
- единую схему данных;
- дедупликацию;
- контроль качества;
- обновление библии;
- сбор финальных таблиц.

### Исследовательские потоки

Запускать волнами по 4–6 задач, а не 20 одинаковых исследований сразу. После первой волны проверять качество и только затем масштабировать.

## Astra / Work / тариф

Официальные материалы OpenAI на дату проверки:

- GPT-6 Astra доступна в ChatGPT Work и Codex для Plus; rollout может быть постепенным: https://help.openai.com/en/articles/20001275/
- ChatGPT Work предназначен для длинных многошаговых задач с браузером, файлами и готовыми результатами: https://openai.com/index/chatgpt-for-your-most-ambitious-work/
- Pro даёт более высокий класс доступа / лимитов и ориентирован на интенсивную профессиональную работу: https://help.openai.com/en/articles/9793128-what-is-chatgpt-pro/

## Решение на старте

**Не считать Pro обязательным для начала проекта.**

Сначала:

1. проверить доступ к Work / Astra на текущем Plus;
2. запустить 4–6 параллельных рабочих пакетов;
3. проверить качество источников и данных;
4. понять реальную скорость сбора;
5. только если лимиты / concurrency становятся bottleneck — переходить на Pro или выделять дополнительные рабочие контуры.

Причина: главная проблема проекта — не интеллект одного запроса, а стандартизация данных и проверка качества.

## Что Astra логично поручить

- сложный market mapping;
- сравнение 20–50 источников;
- исследование локального законодательства с первичными источниками;
- поиск и квалификация крупных застройщиков;
- конкурентные deep dives;
- сложные задачи computer-use, где нужно ходить по множеству сайтов.

## Что можно делать более дешёвыми / быстрыми потоками

- нормализация контактов;
- дедупликация;
- извлечение одинаковых полей с уже найденных страниц;
- классификация агентств;
- проверка активности соцсетей;
- подготовка черновых summary по стандартному шаблону.

## Главный принцип контроля

Любая строка базы должна иметь источник и дату проверки.

AI не имеет права:

- выдумывать email / телефон;
- оценивать комиссию без источника;
- считать компанию действующей только по старому каталогу;
- писать, что договор с застройщиком есть, если он не подтверждён;
- смешивать агрегированные данные и подтверждённые official terms.

## Практическая первая волна

Запустить 6 пакетов:

1. агентства РФ — Центральный ФО;
2. агентства РФ — Поволжье / Юг;
3. агентства РФ — Урал / Сибирь / Дальний Восток;
4. Беларусь + Казахстан;
5. Пхукет: застройщики + сверка существующей базы;
6. конкуренты: marketing channels + партнёрские программы.

После QA масштабировать до полной матрицы из `07-research-agents.md`.
